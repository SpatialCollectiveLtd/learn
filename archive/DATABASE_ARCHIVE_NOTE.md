# Database Archive Note

## Archive Date
March 2026

## Why This Archive Exists
The Learn Platform underwent a full architectural reset as part of Phase A (2026).

**Before reset:** Learn was a self-contained app that owned user identity, attendance, work tracking, contracts, and training — with ~20 database tables, its own auth system, and direct PostgreSQL storage for all data.

**After reset:** Learn becomes a thin platform (LMS + Comms + Dashboards) that delegates identity, authentication, attendance, work tracking, and payments to the DPW Manager App (`app.spatialcollective.com`). Learn's database was reduced to 4 tables: `training_progress`, `notifications`, `notification_recipients`, and `qgis_submissions`.

## What Was Archived

### Backup Locations
- `backups/pre-reset-archive-*/` — Full JSON export of every table (generated by `scripts/full-db-export.js`)
- `backups/youth_participants_backup_*.json` — Youth data backups (from `scripts/backup-youth-data.js`)
- Git tag: `archive/pre-reset-march-2026` — Full codebase snapshot at pre-reset state

### Tables That Existed Before Reset
**Core:**
- `staff_members` — trainer/admin/superadmin accounts
- `youth_participants` — all youth user records
- `contract_templates` — contract template content
- `signed_contracts` — signed contract records with base64 signatures
- `auth_logs` — authentication event log
- `attendance_records` — daily attendance submitted by trainers

**Training:**
- `youth_training_progress` — step-by-step training completion per module

**Work Tracking:**
- `youth_osm_stats` — cached OSM building counts
- `youth_work_days` — daily work period tracking with approval
- `settlement_work_config` — work period config per settlement/program

**Extended:**
- `youth_personal_info` — extended personal info (gender, disability, ward)
- `program_modules` — module definitions with payment rates
- `youth_module_history` — module assignment history
- `youth_module_stats` — generic module work stats
- `youth_module_assignments` — active module assignment tracking
- `youth_notifications` — in-app notifications for youth

**Infrastructure:**
- `settlements` — normalized settlement reference data
- `audit_log` — data change audit trail
- `biometric_credentials` — WebAuthn stored credentials
- `biometric_challenges` — WebAuthn challenge store

### What Was NOT Migrated
Nothing. The reset is a clean start. All historical data is preserved in the archive backups above but is not carried forward. DPW Manager App holds all user identity and work data going forward.

### How to Access Historical Data
1. JSON exports in `backups/pre-reset-archive-*/` — each table is a separate `.json` file
2. The `_MANIFEST.json` file in each archive records row counts and any export errors
3. The `_schema_columns.json` file records the full column definitions at time of export
4. To view the pre-reset codebase: `git checkout archive/pre-reset-march-2026`
